# TAHAP 1 — ANALISIS KEBUTUHAN SISTEM
## Sistem Deteksi Tanaman Melon Siap Pangkas (ESP32-CAM + AI)

---

## 1.1 Latar Belakang Kebutuhan

Sistem ini dibutuhkan untuk mengotomatisasi proses identifikasi kesiapan pangkas pada tanaman melon, yang secara konvensional dilakukan secara manual oleh petani/peneliti melalui pengamatan visual langsung. Proses manual ini bersifat subjektif, tidak konsisten, dan tidak terdokumentasi secara sistematis.

---

## 1.2 Kebutuhan Utama

| No | Kebutuhan | Penjelasan |
|---|---|---|
| 1 | Akuisisi citra otomatis | ESP32-CAM menangkap gambar tanaman secara periodik (~1 detik) tanpa intervensi manual |
| 2 | Inferensi AI realtime | Backend harus mampu menjalankan model TFLite (MobileNetV2 FOMO) dan mengembalikan hasil deteksi dengan latensi rendah |
| 3 | Klasifikasi objek & status | Sistem harus mengenali 5 label dan menentukan status pangkas berdasarkan aturan bisnis yang *configurable* |
| 4 | Penyimpanan riwayat | Setiap hasil deteksi (termasuk bounding box image) harus tersimpan permanen dan dapat ditelusuri |
| 5 | Monitoring kondisi sistem | Pengguna harus dapat memantau status ESP32, backend, database, model AI, dan VPS secara real-time |
| 6 | Visualisasi data | Statistik harian/mingguan harus tersedia dalam bentuk grafik untuk mendukung analisis penelitian |
| 7 | Kontrol akses | Hanya pengguna terautentikasi (dibuat oleh admin) yang dapat mengakses dashboard |
| 8 | Ekspor data | Hasil deteksi dapat diunduh (TXT saat ini, ekstensibel ke PDF/Excel) |

---

## 1.3 Batasan Kebutuhan (Constraints)

- Tidak ada video streaming — sistem bekerja dengan mekanisme *polling/refresh*, bukan koneksi realtime persisten (WebSocket/MJPEG).
- Tidak ada registrasi pengguna publik — manajemen user bersifat tertutup (admin-provisioned).
- Confidence score model diproses secara internal tetapi **tidak diekspos** ke pengguna maupun database — ini adalah keputusan desain penting yang memengaruhi struktur skema data dan response API.
- Database harus *database-agnostic* (PostgreSQL default, MySQL sebagai alternatif) — mengharuskan penggunaan ORM murni tanpa fitur spesifik vendor.
- Deployment pada VPS dengan spesifikasi terbatas (1 vCPU, 4GB RAM) — ini membatasi pilihan arsitektur (misal: tidak feasible menjalankan model besar atau banyak worker proses paralel).
- Aplikasi web hanya dioptimalkan untuk Desktop — tidak perlu strategi responsive mobile-first.

---

## 1.4 Kebutuhan Penelitian

Sebagai bagian dari skripsi, sistem juga harus mendukung:
- Reproducibility hasil deteksi (penyimpanan bounding box image sebagai bukti visual)
- Traceability per perangkat (Device ID) untuk mendukung analisis multi-titik jika diperlukan
- Pencatatan durasi inferensi sebagai metrik performa model yang dapat dianalisis dalam laporan skripsi
